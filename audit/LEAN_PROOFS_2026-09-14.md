# USL Lean 증명 — 2026-09-14

사용자 요청: “USL 을 lean4 로 증명해줘봐”. 통합 시점의 10개 모델 정리에 27개를 추가해 **37개 정리**를 Lean 4.33.1로 검사했다.

핵심 결과는 실행 가능한 유한 홉 탐색과 `PathWithin` 명세의 동치다. 모든 그래프·출발·도착 자원·자연수 홉 예산에 대해 성립하며, 유한 경로에는 충분한 탐색 예산이 존재함도 증명한다. 구조 검사와 역할 방향, 링크 선택의 보존성, 읽기 요청과 허용 범위의 교집합, 요청 예산 초과 거부도 증명했다.

`Examples/ProofAudit.lean`이 모든 모델 정리를 내보내고 통합 테스트가 전이적 공리 의존성을 검사한다. 허용한 기반 공리는 `propext`, `Classical.choice`, `Quot.sound`이며 `sorryAx` 또는 사용자 정의 공리는 허용하지 않는다. 전체 정리 이름·타입·실제 공리 목록, 관련 소스의 SHA-256, 검증 명령 결과는 [기계 판독 기록](lean-proofs-2026-09-14.json)에 있다.

검증 결과:

- `npm run test:lean`: Lean 빌드와 통합 테스트 4개 통과. 37개 정리 공리 검사, 기존 export 실패 처리, TS 대조 383건 포함.
- TS 대조: 경로 100건, 역할 방향 80건, 읽기 예산 192건, 그래프 구조 11건. 읽기 예산 초과 시 실제 resolver 호출이 없음을 확인했다.
- `npm test`: 기존 테스트 210개 통과.
- `npm run typecheck`, `npm run build`: 통과.
- `python3 scripts/check-docs.py`: 현재 문서 링크와 동결된 아카이브 23개 해시 통과.

증명 대상은 [Lean 모델](../docs/LEAN4_INTEGRATION.md#형식-검증-범위)이다. TS 전체 구현과 외부 의미의 정확성을 증명한 것은 아니다. 구조 모델에 없는 문법·metadata·locator·출처 검사, TS BFS의 모든 제한 조합, 외부 IO는 별도 검증 대상이다. 기존 통합·RDF 검증 영수증은 당시 소스의 기록으로 그대로 보존했다.
