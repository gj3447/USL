## 이 지시에 따른 구현 선택

| 결정 | 결과 | 구분 |
|---|---|---|
| DB를 추가하지 않는다 | 원본 시스템 읽기 → 임시 해석 → 결과 반환 | 사용자 방향의 구현 |
| 자원 종류와 접근 수단을 분리한다 | 열린 `types` IRI + 기존 locator/host callback | AI 설계 선택 |
| 의미·역할·출처를 보존한다 | 이름 있는 다자 링크, 명시적 provenance, 독립 digest | AI 설계 선택 |
| Lean 4를 양쪽 범위에 사용한다 | `#usl_export`, TS adapter, 10개 모델 정리, 동작 대조 | 사용자 범위 + AI 구현 |
| 표준의 실제 지원 범위를 명시한다 | JSON-LD/RDF 출력, PROV-O 출처, SHACL 구조 검사 | AI 설계 선택 |
| 과거 문서를 원문 보관한다 | 23개 문서의 수정 전 바이트와 SHA-256 manifest | 사용자 지시의 구현 |

단항 자원 설명, `resource-graph/v1`, `lean4/v1`, `urn:usl:vocab:`는 구현 규약이다. 이것을 사용자가 세부 스키마까지 비준한 발화로 바꾸지 않는다. HSWM의 “치환” 및 schema admission의 구체적 의미는 이번 지시만으로 닫히지 않는다.
