# USL 결정 기록

현재 기준: 2026-09-14. 사용자 요구와 구체적인 구현 선택을 분리한다. 원격 KG에 새 판정을 쓰거나 과거 UserVerdict를 수정하지 않는다.

## 사용자 지시

이 세션의 사용자 원문:

> 그 db 는 아니고 그냥 문법같은거지 ㅇㅇ? 마지막 개발 내용이 머냐 그 db 새로 kg 가은거 만들고 있길래 식겁햇엇는데

> lean4 랑도 연동되야해 ㅇㅇ 내가 그말을 못햇엇어

> 싹다 커밋해서 푸시해줘 드리프트 된 내용 과거는 레가시 아카이빙 해주고 ㅇㅇ 표준 그래프 엔지니어링으로 다시 정리좀 해줘봐봐 ㅇㅇ. 범위 둘다 최대한 많은범위를 연결할수 있게 ㅇㅇ

마지막 “둘 다”는 이 세션에서 제시한 두 범위, **Lean 선언·증명과 다른 자원의 연결**, **USL 자체 성질의 Lean 형식 검증**을 가리킨다.

이전 원개념은 롱기누스의 최소단위, 의미를 담아 자원을 연결하는 접착제, HSWM 확장개념이다. 이후 사용자 발화에서 언어적 성격, TypeScript + Effect 함수형 구현, 인터넷 공간의 시멘틱 어댑터를 지정했다. [이전 언어 문서의 원문 기록](LANGUAGE.md#사용자-정의와-설계의-출처)과 [보존된 후속 발화](../archive/2026-09-14-before-consolidation/docs/SEMANTIC_ADAPTER_DESIGN.md)를 참고한다.

## 이 지시에 따른 구현 선택

| 결정 | 결과 | 구분 |
|---|---|---|
| DB를 추가하지 않는다 | 원본 시스템 읽기 → 임시 해석 → 결과 반환 | 사용자 방향의 구현 |
| 자원 종류와 접근 수단을 분리한다 | 열린 `types` IRI + 기존 locator/host callback | AI 설계 선택 |
| 의미·역할·출처를 보존한다 | 이름 있는 다자 링크, 명시적 provenance, 독립 digest | AI 설계 선택 |
| Lean 4를 양쪽 범위에 사용한다 | `#usl_export`, TS adapter, 10개 모델 정리, 동작 대조 | 사용자 범위 + AI 구현 |
| 표준의 실제 지원 범위를 명시한다 | JSON-LD/RDF 출력, PROV-O 출처, SHACL 구조 검사 | AI 설계 선택 |
| 과거 문서를 원문 보관한다 | 23개 문서의 수정 전 바이트와 SHA-256 manifest | 사용자 지시의 구현 |

단항 자원 설명, `resource-graph/v1`, `lean4/v1`, `urn:usl:vocab:`는 구현 규약이다. 이것을 사용자가 세부 스키마까지 비준한 발화로 바꾸지 않는다. HSWM의 “치환” 및 schema admission의 구체적 의미는 이번 지시만으로 닫히지 않는다.

## 후속 형식 증명 요청 — 2026-09-14

> USL 을 lean4 로 증명해줘봐

기존 10개 모델 정리를 37개로 확장했다. 유한 홉 탐색과 경로 명세의 동치, 경로 완전성, 그래프 구조 검사, 역할 방향, 링크 선택, 읽기 허용 범위·예산을 증명한다. 모든 정리의 전이적 공리 의존성을 검사하고 TypeScript와 383건 대조한다. 이는 위 통합 작업 이후의 추가 구현이며, 이전 검증 영수증을 수정하지 않는다. [현재 증명 범위](LEAN4_INTEGRATION.md#형식-검증-범위)와 [실행 기록](../audit/LEAN_PROOFS_2026-09-14.md)을 참고한다.
