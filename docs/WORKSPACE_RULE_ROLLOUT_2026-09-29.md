## 적용한 계약

HSWM 연결 실행에는 USL repository/resource/workspace/representation 등록, 지정 수신자, 작업환경 소유자가 승인한 프로젝트 접근 범위·목적·만료·철회, 실제 승인된 전송 경로의 제한된 읽기 확인이 필요하다. 조건을 충족하지 않으면 에이전트는 `NOT_READY`로 중단한다.

이 전파는 에이전트 지침의 적용이다. 다른 사용자의 실제 접근 권한을 발급하거나 원격 등록 서버를 배포한 작업이 아니다. 호스트·인증 제공자에서 접근을 집행해야 하며, 지침을 읽지 않는 프로그램에 대한 실행 차단이나 이 규칙 자체의 Lean 증명은 제공하지 않는다. [절차와 구현 범위](WORKSPACE_LINKING.md).

## 검증과 보존

- 정책 블록 SHA-256: `cd4085f132b27e325b39f900668660eb3fbbf7f53423bdda6d301965e6c6b621`.
- 85개 원격 파일을 최초 스냅샷과 공통 블록으로 재구성한 바이트와 대조했다. 기존 지침을 보존했고 심볼릭 링크는 정본 파일을 수정해 유지했다.
- 기본 브랜치 직접 변경, 단일 writer, 서명된 커밋과 PR 등 저장소별 절차를 사용했다. 보호 규칙을 우회하지 않았다.
- 로컬 installer 테스트 3개, GitHub 동기화 모의 테스트 10개, 문서 링크·아카이브 해시 검사, 공학 반례 25개 재실행과 산출물 일치 검사, binding-progress 검사를 통과했다.
- 기존 문서의 절대 경로 링크 34개를 상대 경로로 수정했다. 문서 검사는 이제 절대 파일시스템 링크를 거부한다. 동시 반영된 CHU 연결의 package 변경도 현재 공학 소스 pin에 반영하도록 검사를 재실행했다.
- 별도 검증을 요구하는 5개 저장소 중 4개는 필수 검증을 통과했다. **`ooptdd-loop`의 `scripts/verify_ooptdd.sh`는 기존 `tests/test_omd_bridge.py:7–8`의 E402 두 건으로 실패한다.** 문서화된 ruff 0.4.10에서도 확인했으며, 해당 규칙 커밋 본문에 실패를 명시했다. 원본 코드나 검증 기준을 변경하지 않았다.

개별 private 저장소 이름, 로컬 경로와 커밋 영수증은 공개 문서에 싣지 않았다. 상세 전파·원격 검증 결과는 Git에서 제외한 `.usl/local/rollouts/`에 보관한다. 다른 기존 checkout은 새 기본 브랜치 커밋을 가져와야 규칙이 적용된다.
